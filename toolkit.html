OOP Exam & Viva Survival Guide

Author: Ali Raza Saleem (BSCS / AI Engineering) Subject: CS201 / CS301 (Object Oriented Programming) Language: C++ / Python concepts
💡 Exam Note: This guide strips away university lecture slides clutter. It gives you the exact definitions, mental models, and code traps tested on midterm/final exam papers and in lab vivas.

1 The 4 Pillars — In Plain English

Pillar What Textbooks Say The Intuitive Mental Model Viva One-Liner
Encapsulation Binding data and functions into a single unit. Data Hiding & Security. Make variables private; allow access strictly through getters/setters so nobody corrupts internal state. "Wrapping data with methods and restricting direct access to protect data integrity."
Abstraction Hiding implementation and showing only essential features. The TV Remote. You press the power button; you don't need to know circuit board voltages inside. "Displaying only essential interfaces while hiding internal complexity using abstract classes."
Inheritance Deriving a new class from an existing class. Code Reusability. A Student is a Person. Write common code once in the parent class. "Deriving child classes from parent classes to eliminate code duplication."
Polymorphism Ability of a message to take multiple forms. One Name, Many Actions. Call speak(): a Dog barks, a Cat meows. Same function name, different behavior. "Same function call executes different code based on the actual object at runtime."

2 The #1 Exam Trap: Compile-Time vs Runtime

Almost every CS professor tests whether you understand Early Binding (Compile-Time) vs Late Binding (Runtime).

Compile-Time (Early Binding) Static
  • Examples: Function Overloading, Operator Overloading.
  • Compiler decides which function to call at compile time.
  • Zero runtime performance overhead (faster).
Runtime (Late Binding) Dynamic
  • Examples: Function Overriding with virtual.
  • Decision made at runtime using a VTable (Virtual Table).
  • Requires a Base pointer pointing to a Derived object!
// RUNTIME POLYMORPHISM IN C++
#include <iostream>
using namespace std;

class Animal {
public:
    // Without 'virtual', pointer type determines the call (Animal)
    // With 'virtual', actual object type determines the call (Dog)
    virtual void speak() {
        cout << "Generic sound" << endl;
    }
    virtual ~Animal() {} // Mandatory virtual destructor!
};

class Dog : public Animal {
public:
    void speak() override {
        cout << "Woof! Woof!" << endl;
    }
};

int main() {
    Animal* a = new Dog(); // Base pointer -> Derived object
    a->speak();            // Outputs: "Woof! Woof!" because of virtual
    delete a;
    return 0;
}

3 Memory & Constructors: Where Students Lose Marks

1. Shallow Copy vs Deep Copy (Viva Favorite 🔥)

The default C++ copy constructor does a Shallow Copy: it copies member variables byte-by-byte. If your class has a pointer int* data, both the original and copied object point to the exact same memory address on the Heap.

⚠️ The Crash: When object 1 destructs, it deletes the heap pointer. When object 2 destructs, it tries to delete already-freed memory → Double Free Corruption Crash!

The Fix (Deep Copy): Allocate a fresh new memory address in the copy constructor and copy the data value into it: 

class Student {
    int* rollNo;
public:
    Student(int r) {
        rollNo = new int(r); // Heap allocation
    }

    // CUSTOM DEEP COPY CONSTRUCTOR
    Student(const Student& other) {
        rollNo = new int(*other.rollNo); // Brand new address, independent value!
    }

    ~Student() {
        delete rollNo; // Safe from double-free crashes
    }
};

2. Why Base Destructors MUST Be Virtual

If you execute Base* ptr = new Derived(); delete ptr; and the Base destructor is not virtual, the compiler executes only ~Base(). Any memory or files opened in Derived will leak forever. Always declare: virtual ~Base() {}.

5 Top 10 Rapid-Fire Lab Viva Questions

Memorize these exact 10-second answers for your lab instructor or external examiner:

1. Can a constructor be virtual?

No. A virtual function requires a virtual table pointer (vptr) which only exists after the constructor finishes constructing the object.

2. Can a destructor be virtual?

Yes. And it must be virtual in base classes to prevent derived class memory leaks when deleting through base pointers.

3. What is a Pure Virtual Function?

A function declared as virtual void func() = 0; with no definition in the base class. It forces derived classes to implement it.

4. Can you instantiate an Abstract Class?

No. You cannot create direct objects of an abstract class. You can only create pointers and references to it.

5. What is the Diamond Problem?

Ambiguity in multiple inheritance when a class inherits from two classes that share a common grandparent. Fixed with virtual inheritance.

6. Does a `friend` function break encapsulation?

Yes, technically. It bypasses private access limits, so use it sparingly (mainly for operator overloading).

7. What is the `this` pointer?

An implicit constant pointer passed to non-static member functions holding the memory address of the calling object.

8. Difference between Struct and Class in C++?

Default access level only. struct members are public by default; class members are private by default.

9. What is Object Slicing?

When a derived object is assigned by value to a base object (Base b = derivedObj;), slicing off all derived-specific attributes.

10. Can you overload by return type alone?

No. The compiler requires differences in parameter count, types, or order. Return type alone is not enough.
